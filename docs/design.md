# Design notes

## Why Python

The critical path combines data aggregation, gradient boosting and remote model calls. Python gives one typed interface across pandas, scikit-learn, LangChain and Hugging Face. A C++ extension would add build complexity before a measured bottleneck warrants it. Account timestamps and cumulative amount arrays use NumPy binary search instead of rescanning the full transaction table per tool call.

## Evidence boundary

The validated dataset holds labels solely for evaluation. `EvidenceStore` copies an explicit four-column allowlist without labels. Account history is calculated at the transaction's timestamp, with a strict `< timestamp` predicate. The 1-hour and 24-hour intervals include the left boundary and exclude the right boundary. Same-time rows never see each other.

A tool closure captures the active transaction ID. Its Pydantic schema forbids extra fields and rejects type coercion; the closure rejects any different ID. The model cannot request raw SQL, arbitrary files, shell commands, or arbitrary account histories.

Tools return numeric aggregates; the only free-text field generated by the model is its rationale. A rationale can still be wrong. Gates enforce evidence availability and tool citations, not logical proof of every sentence.

## Agent protocol

The agent binds two investigation tools plus a `submit_verdict` schema. It accepts structured tool calls only. Malformed JSON, invalid arguments, unknown tools and fabricated citations consume a repair budget. Tool errors produce tool messages that let the model correct its call. Invalid JSON responses are replaced by a repair turn so invalid assistant tool-call records do not poison the next provider request.

A final verdict must be the only call in its turn. This prevents a verdict from relying on tool results the model has not yet received. For automatic decisions, both tools must have succeeded, both must be cited, history must contain at least three earlier transactions, and confidence must reach 0.8. A provider exception is redacted and routes immediately to review rather than blindly retrying a potentially billed request. A maximum of six model turns bounds work.

The review queue is a JSONL artifact, not a staffed review service. Connecting it to a case-management system and recording reviewer outcomes would be separate work.

## Benchmark scope

Chronological splitting reflects deployment more closely than shuffled train/test splits. The feature cache may contain the whole stream, but every query is time bounded and the regression tests verify invariance to future changes. Real fraud labels often arrive late; this benchmark assumes training labels are available at the split and does not model a delayed-label gap.

The validation F1 threshold is the forced binary baseline policy. The alert threshold is a different policy: the 90th validation-score percentile. Test alert rate need not be exactly 10% because score ties and temporal drift can change it. Sampling is reproducible and uniform over eligible alerts, not balanced on ground truth.

Replay is a deterministic test double using actual LangChain messages and actual tools. It verifies orchestration, logging and measurement. It does not emulate language understanding, provide a live model latency estimate, or establish LLM accuracy. The benchmark schema records the backend prominently to prevent conflation.

Costs combine provider-reported tokens with supplied rates and a fixed human-review assumption. Unknown usage remains unknown. Reported runtimes exclude feature construction and network setup; the agent per-case time includes binding, model calls, tool execution and validation. No dollar value is assigned to baseline compute. Neither policy is credited with the unknown result of a human investigation.

## Next experiments

Run a real tool-capable HF model on a larger fixed alert cohort; evaluate multiple models on the same IDs. Fit a confidence calibration or risk-controlled abstention policy using a separate validation cohort. Add confidence intervals, delayed-label splits and drift tests. Assess the cost of mistakes and human decisions rather than optimizing token cost alone. Optimize storage only after profiling larger streams.
